# 游戏运行时重构实施步骤

状态：缩小范围后的实施计划，不记录进度，不表示新协议已可用。
适用任务：分阶段实施游戏运行时重构。
相关代码：`src/shared/game-card/`、`src/renderer/chat/`、`test/game-card/`。
前置文档：[目标设计](./game_runtime_design.md)、[构建与测试](../engineering/build_and_test.md)。

## 执行约束

- 仅交付 main.js 顺序编排多 Agent、共享变量，以及现有界面和演出的接入。
- 每一步在列明的依赖完成后独立可测试、可验收、可提交。
- 不承诺旧卡兼容，不保留长期双执行器；完整闭环交付前不向普通玩家开放新协议。
- 复用规则、模型传输、资源和存储能力，不引入独立前端宿主或并发任务系统。
- Schema、实现和契约测试同步更新；仍成立的测试保留，旧语义用例按新契约替换并说明原因。
- 仓库文件不超过 200 行；遵循仓库对游戏卡内容资产的例外规定。

## 测试方式

准备独立的 Judge/Narrator 小型 fixture，不用 WA2 承担所有基础测试。
单元测试验证执行语义；集成测试验证模块组合；E2E 验证双端输入、显示、资源和保存恢复。
模型采用可控假传输，流式 E2E 使用本地 SSE 服务，不依赖真实密钥或随机输出。
异步测试用显式屏障控制时序，不增加固定等待掩盖问题。

代码步骤执行 lint、diff 检查及相关测试，按影响范围运行 JS、集成、Rust 和双端构建。
最终按现有 CI 策略完成浏览器和桌面 E2E，不额外增加重复安装包构建。
纯文档修改不冒充实现验收，也不需要运行产品测试。

## 步骤 1：确定新清单和最小执行契约

依赖：无。

- 交付：定稿协议版本、main.js 入口、Agent 文件和模型引用，保留现有 State、资源和显示配置。
- 明确调用句柄、原始 response、最终 msg 及跨 Agent 消息只读引用；区分调用完成和阅读完成。
- 定稿 reader 双来源/双模式、两种 patch 的提交归属及段落边界，API 命名不以示例代替正式契约。
- 更新唯一 Schema 和加载校验；新定义先供测试加载，缺失能力不得静默回退。
- 测试：有效定义、缺入口、非法 Agent/路径/模型引用、未知或旧协议；验证 JS/Rust 一致性。
- 验收：最小卡加载为明确运行定义，错误定位文件/字段；不引入 UI 入口或前端通信配置。

## 步骤 2：独立 Agent 调用与共享变量

依赖：步骤 1。

- 交付：从现有生成流程提取必要的无显示调用能力，按 Agent 维护 Messages、初始化及规则上下文。
- 复用 State 校验和 patch；隐藏调用完整消费后再允许下一次调用，暂不接入 main.js。
- 测试：上下文/TTL/init 隔离、跨 Agent 消息快照引用、变量传递、规则阶段、校验失败和取消。
- 验证原始 response 不受 post_response 改写，最终 msg 可按 ID 查询；普通 patch 只提交一次。
- 验收：测试代码顺序调用两个 Agent 并完成变量传递，不产生可见消息，非法并行调用被拒绝。
- 保留普通聊天相关回归；不以旧游戏卡语义完全不变为目标。

## 步骤 3：受控 main.js 与一轮输入

依赖：步骤 2。

- 交付：受控脚本宿主、卡内模块加载、可选 onStart、onInput 和 State/Agent 接口，接入平台现有输入入口。
- 新 Session 按声明顺序执行全部 Agent init，再执行 onStart；启动失败保留现场但不标记成功，重试从初始化前重跑；启动中的输入排队，完成后才执行。
- 支持 JS 结算及顺序调用，限制同一 Session 重入，取消未完成调用及阅读。
- 建立整轮内存重试基准；失败停止并保留已发布的 State、Agent 数据和演出，仅 retry 恢复基准；失败现场禁止保存，停止后拒绝迟到写入。
- 测试：真实宿主的顺序流程、JS 分支、模块越界、失控计算终止、第二个 Agent 失败、整轮重试和取消。
- 验收：输入完成 Judge → JS → Narrator；失败不留下半轮上下文，脚本不能访问宿主或密钥。

## 步骤 4：实现 reader 并接入现有演出

依赖：步骤 3。

- 交付：reader 接收字符串/文本流，支持分段/非分段模式；present 驱动阅读并保存实际展示记录。
- 复用现有 msg 历史页面，在页面标题栏增加 Agent 切换按钮，展示当前 Session 对应 Agent 的实际 Messages。
- 分段 next() 提交该段 state_patch_stream 后返回正文；非分段仅输出增量，两种模式均过滤普通 patch。
- 隐藏调用不等待阅读，不提交阅读 patch；将可见记录、阅读和演出恢复纳入整轮失败处理。
- 测试：双来源 × 双模式、跨 chunk 标签、预读不提交、末尾空正文 patch、顺序和取消、非法 patch。
- 验证 post_response 改写只影响静态来源、删除目标消息、普通 patch 不重复、模型完成不代表阅读完成。
- 验证历史切换、辅助 Agent/空历史、规则修改后的消息及跨 Session 数据隔离；查看不触发调用或变量修改。
- E2E：本地 SSE、辅助消息隐藏、背景/立绘/BGM 随阅读更新；失败后保留现场、重试才恢复基准，不透明重播副作用。
- 验收：双端可选择实时原始输出或最终 msg；均支持 reader 模式，无需独立卡内前端。

## 步骤 5：扩展现有 Session 保存恢复

依赖：步骤 4。

- 交付：带版本的 Session 数据，保存全部 Agent 数据、共享 State、可见记录及必要视图数据。
- 整轮完成后保存一致结果；运行中禁用显式保存，不持久化半轮数据，不恢复执行中的脚本。
- 桌面自动保存，Web 显式创建新存档；不迁移旧卡存档，不新增检查点 API。
- 测试：读写往返、下一轮上下文正确、init 不重复、写入失败、损坏档保护和 Session 隔离。
- 验证原始流展示与最终 msg 不同时仍恢复实际展示记录，历史回看及读档不重新提交阅读 patch。
- 验收：双端完成一轮、保存、重启并继续，各 Agent 历史与可见记录正确恢复。

## 步骤 6：迁移示例卡并完成双端交付

依赖：步骤 1–5。

- 交付：新卡接通导入、Web 发布缓存、dry-run、模板和开发参考；trace 标注 agentId/callId 与脚本来源。
- 迁移 WA2 入口和 Agent 定义，复用提示词、资源和仍成立的规则，验证实际体验。
- 提供旧卡版本提示和迁移说明；酒馆转换未支持新协议时明确阻止旧产物进入新运行流程。
- 测试：导入/下载至游玩恢复主线、缺资源、静态检查不请求模型、日志定位及密钥排除、普通聊天回归。
- 验收：按现有 CI 策略通过单元、集成和双端 E2E 后开放新协议，不留旧执行器作为兼容承诺。

## 后续单独评审

并行和后台任务、卡内独立 UI、资源桥、演出库提取、检查点及脚本恢复。
依据迁移卡的实际需求决定是否增加，不提前建设这些基础设施。
