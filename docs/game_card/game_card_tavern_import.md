# 酒馆卡导入与转换

## 功能与边界

导入使用游戏卡容器、规则引擎和 [worldbook library](../../libs/worldbook-library/README.md)。

将 V2/V3 酒馆角色卡转换为当前 schema 下的普通游戏卡。导入时理解酒馆格式和常见宏，运行时只使用现有 rules、Content、state、受控 exec 和随卡分发的世界书库。不新增“酒馆卡”运行类型、特殊 lib 类型、exec args 分区或通用酒馆宏解释器。

只做导入，不设计酒馆格式导出、完整提示词预设迁移、插件运行环境或跨卡全局变量系统。转换后的目录是运行时依据，原始酒馆数据只归档追溯，不在每次加载时重新转换。

## 支持范围

- 同一入口支持 V2/V3 JSON、PNG/APNG 和 CHARX，原生 PNG/ZIP 保持原路径；酒馆卡经内置 Worker 编译、后端 stage 校验后自动安装，仅有实质性兼容差异时确认。默认新 ID；更新须主动选择目标并单独确认覆盖，提交时再次检查目标及生成状态。
- 转换角色定义、主提示词/历史后指令及 original、隐藏示例、候选开场白和世界书。真实开场白不带 TTL，空开场白也持久化初始化状态；世界书关键词/正文通过普通 JS 回调在匹配/预算前渲染。
- 宏配置为 `common-sequential-v1`：char/user、original、newline/noop、getvar/setvar/addvar/incvar/decvar（静态变量名）、random/pick、简单 NdN roll、reverse、comment/`//`、hidden_key、最近真实消息及提示段 outlet。支持内联嵌套参数；固定位置 pick 使用持久化会话种子。
- scoped/if、动态变量名、时间/宿主宏、全局变量、插件脚本、旧引擎按宏类型分批求值等不模拟，未知宏整体保持原文并警告；世界书中只读/随机宏可用，写变量或读取自身 outlet 的宏不执行。
- 保留原始 JSON、转换选项、源指纹、变量/条目/资产映射及兼容报告；卡内 library 和文档一并复制并记录 SHA-256。已编译宏文本修改后必须重新转换，不使用旧文本索引。
- CHARX 本地资源、PNG 默认 icon 和限量图片 data URL 支持受控复制；背景/表情注册资源表，其余媒体仅归档，不自动显示立绘或播放。外部 URL、任意本地文件、旧式 PNG 扩展资源不读取，缺失资源显示警告。
- 正则按 [正则转换](./game_card_tavern_regex.md) 映射到 display 和普通 exec；统一修改 messages，不新增 request 阶段或保留请求专用历史，接受提示词正则造成原文丢失。
- 当前限制：源 JSON 16 MiB/64 层、单文本 4096 宏节点、世界书最多 3500 条、生成文本 64 MiB、总文件数 4096；取消转换会终止 Worker 并清理任务，容器读取期间暂不提供可中断的字节级进度。
- 不提供来源指纹重复提示或会话内开场白选择 UI。接受源字段不等于支持其运行语义；有 warning 时提示差异，用户可直接继续或取消。

主要代码：`src/shared/tavern-import/`（纯转换）、`src/renderer/gameCard/compileTavern.js`（Worker 编排）、`src/tauri/src/tavern_*.rs`（容器/授权/安装）。验证命令见 [构建与测试](../build_and_test.md)。

## 统一导入入口

复用“导入卡片”按钮，直接选择文件，不另设类型菜单或“导入酒馆卡”按钮。选择器接受 `.gamecard`、`.png`、`.apng`、`.json`、`.charx`。选择无 `spec` 的平台项目 `card.json` 时导入其完整目录；有 `spec` 的 JSON 仍按酒馆格式识别，同名文件和未知 `spec` 不回退为目录导入。卡片行的“用酒馆卡更新”仅接受酒馆源文件，平台项目入口和原生容器均在安装前拒绝。

- 平台游戏卡：保持原导入路径，不额外要求酒馆转换确认。
- 酒馆卡：自动使用默认配置转换、校验并导入，显示成功结果；无风险不弹出转换选项或预览页。只有不支持的宏、功能扩展、缺失依赖等兼容差异才提示“继续导入 / 取消”。
- 无法识别或文件损坏：说明原因，不引导用户换按钮重试。

桌面导入默认使用用户显示名 `User`、开场白索引 `0`、空的默认主提示词和历史后指令，不要求配置这些字段。编译核心仍接受显式选项并随卡保存，但不作为导入必经 UI。用户/persona 信息不从模型配置或聊天文本猜测，也不把 API 密钥等模型配置带入产物。

普通导入始终新建副本。更新已有卡从列表中该卡的“用酒馆卡更新”主动发起，选择源文件后单独确认目标 ID、资源覆盖及存档风险；即使没有兼容警告也须确认。兼容差异与覆盖分别确认，接受前者不代表接受后者。此更新入口仅接受酒馆源卡，误选原生包在安装前拒绝。

准备、转换和校验期间显示阶段及进度，禁止重复提交。校验或必要确认完成前不改变 active card。转换期间可以取消并终止 Worker，校验中的取消等待后端返回后清理；进入原子安装后不再提供取消。生成期间禁止导入，安装前再次检查生成状态和更新目标。

## 格式识别与源数据校验

先看文件 magic，再看容器内容和角色卡 `spec`，扩展名只用于文件选择。平台 PNG 的 `gcAr` 与酒馆 PNG 的文本 chunk 是两套容器语义，不能混用。平台容器规则继续见 [分发容器](./game_card_packages.md)。

| 输入 | 识别及处理 |
| --- | --- |
| 平台 `.gamecard` / ZIP | 安全解包后识别根 `card.json`，平台 schema 输入直接进入原管线 |
| 平台 PNG | 存在 `gcAr` 时优先按平台容器严格校验；同时携带酒馆数据时报告采用的平台数据 |
| 酒馆 PNG/APNG | 读取 `tEXt` 中 `ccv3` 或 `chara`，校验 Base64、UTF-8 和 JSON；两者都有时优先 `ccv3` |
| 酒馆 JSON | 识别 `chara_card_v2` / `chara_card_v3`，读取其 `data` |
| CHARX | 安全解包，根 `card.json` 按角色卡解析；资源来自包内清单 |

已选中的平台 payload 或 `ccv3` 损坏时直接报错，不静默降级到另一份数据。重复的同名角色数据 chunk、冲突路径或歧义入口拒绝导入。没有卡数据的普通图片明确报错。V3 容器与优先级依据 [V3 嵌入规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md#embedding-methods)。

先校验源角色卡，再校验生成的游戏卡，不能将原角色 JSON 直接交给平台 schema。已知可补齐的缺省字段使用明确默认值并记录修复；字段类型错误不做任意字符串化。未知字段保留，未知 spec 拒绝；已知 spec 的较新版本保留已知部分并提示版本差异，不仅因版本号不同拒绝。

文件容器版本、角色卡版本、宏语义、世界书语义分别记录。V3 卡不自动等于酒馆新宏引擎，SillyTavern 导出的 V3 世界书也不必采用纯 V3 匹配语义。导入器依据可识别特征和明确选项决定兼容模式，并写进报告。

## 导入管线与职责

```txt
选择文件 -> 安全读取/解包 -> 识别及归一化
        -> 编译临时游戏卡 -> read_card/$import + schema/资源校验 + 报告
        -> 无风险自动继续 / 有兼容差异时确认 / 更新时单独确认覆盖 -> 安装并激活
```

1. Rust 容器层复用 PNG/ZIP 底层能力，读取酒馆数据；输入解包目录与输出游戏卡 staging 分离，不能直接把原 CHARX 当游戏卡安装。
2. 转换器位于 `src/shared/tavern-import/`，接收普通 JSON、资源清单及选项，输出文本文件、资源复制计划和报告；不依赖 DOM、Node 文件系统或 Tauri。
3. Renderer 编排内置转换器、自动导入及按需确认；大输入在内置 Worker 中处理，不执行输入卡附带的程序，也不要求桌面应用另启 Node。
4. Rust 用短期任务 token 管理已授权源资源，返回资源标识而非任意磁盘路径。提交时重新检查输出路径、复制来源、数量、大小及最终卡结构；取消或失败清理本任务目录。
5. 最终安装复用现有 Session 保留和替换流程。无论自动还是确认后安装，都只提交本次 stage 返回的 revision，绑定源数据、选项、目标及产物；修改计划必须重新编译校验，旧 revision 不能安装。

准备、提交、取消能力通过 [平台 adapter](../platform_adapter.md) 的业务接口暴露，组件不直接调用 native 文件 API。转换核心与 Rust 容器编解码各维护一份实现。

## 生成目录及字段映射

```txt
card.json
files.json
state/schema.json
rules/
content/                 # 角色字段、开场白、示例及卡专属配置
scripts/                 # 编译生成的普通 JS，仅在需要时生成
worldbook/config.json
worldbook/entries/        # 一条 entry 一个 MD
lib/worldbook/           # 卡内通用库；连同文档固定版本分发
assets/
import/                  # 原始角色 JSON、映射、版本和兼容报告
```

没有对应内容时不生成空目录、空 action 或空规则。`card.json` 通过现有 `$import` 拆分规则和资源，`stateSchema` 指向状态定义。原始 extensions 不散落到平台 schema 顶层；`import/` 不注册到 `files`、不注入提示词、不引用其中的脚本。

| 角色字段 | 转换目标 |
| --- | --- |
| name / creator / character_version | 游戏卡 name / author / version；空内容版本使用转换器明确默认值 |
| description / personality / scenario | 独立角色定义消息；description 是角色设定，不仅是卡片列表简介 |
| system_prompt | 主提示词规则，非空覆盖对应默认值，空值使用默认值 |
| post_history_instructions | 聊天历史之后的提示规则，覆盖规则同上 |
| first_mes / alternate_greetings | 默认及候选开场白文本，只选择其中一条初始化 |
| mes_example | 独立的隐藏示例消息；解析角色及多行正文，不计入真实历史 |
| character_book | 世界书配置、MD 和卡内 library 调用 |
| nickname | V3 角色宏显示名；缺失、空字符串或 null 时回到 name；null 归一化仅记 info，数字、对象等类型仍拒绝 |
| creator_notes、多语言说明、tags、source、日期、未知扩展 | 展示元信息或归档，不自动加入模型提示 |
| group_only_greetings | 归档并提示群聊未支持，不混入单角色开场白候选 |

主提示词和历史后指令分别绑定自己的默认文本。`{{original}}` 引用未被卡片覆盖时的对应默认值，不等同于平台 `{{original_content}}`，也不代表整个历史。[V2 字段语义](https://github.com/malfoyslastname/character-card-spec-v2/blob/main/spec_v2.md#system_prompt)

默认提示词来自明确的转换配置并随卡保存，不静默引入酒馆全局预设。示例对话按 `<START>` 和说话人标识解析；不能可靠分角色的片段保留为隐藏文本并报告，不能伪造成真实玩家消息。

## 生成规则的生命周期

### 初始化

状态默认值通过 schema 补齐，不覆盖已有存档。空会话的 `init` 初始化必要的稳定种子，求值选中的开场白，生成并保存一条真实 assistant 消息；非空会话加载不重复插入或执行开场白中的变量修改。

默认使用索引 0，候选开场白只保存不同时注入。平台不提供每会话开场白选择 UI。开场白为空时不插入空消息，状态初始化仍应只执行一次。

### 每次发送

1. 仅清理本转换器负责的旧临时消息；先执行用户输入/发送正则，直接更新真实历史，不保留另一份原文。
2. 计算不依赖本轮世界书的动态内容，在真实历史之前放入主提示词、角色定义和示例；角色段落使用稳定 `_meta.source` 作为世界书锚点。
3. 调用卡内 worldbook library，基于真实历史完成匹配、预算、递归及插入。
4. 填充依赖本轮 outlet 的待求值片段，再放置历史后指令；不能为填充 outlet 重跑已执行的随机或写变量宏。

临时定义和示例消息设置 `llm_only`、`ttl: 1`。开场白作为真实消息保留于存档和 retry base，不能被临时提示清理逻辑删除。示例的 user/assistant role 不意味着它们是真实对话，历史查询、世界书深度和计数均须排除这些隐藏示例。

原始模板与已渲染消息分离，每次仅重建动态提示，不重新解释全部聊天历史或模型输出。没有需要转换的响应后逻辑时，不生成 `after_response` 规则。最终模型协议仍由现有 adapter 处理，不承诺不同模型协议能保留完全相同的 system 深度或 assistant prefill 效果。

## 宏编译与运行语义

导入器按 `common-sequential-v1` 解析、检查宏并生成卡内脚本与文本索引；不会在导入时求出所有动态值，也不提供完整酒馆宏解释器。支持范围以上文清单为准，未知宏及其嵌套内容保持原文并报告，不部分执行。

会话变量使用转换器私有命名空间和安全键映射，不直接把源变量名拼成任意 state 路径。赋值、读取按文本顺序求值；固定位置的 pick 使用持久化种子。同一求值节点在一次扫描中复用结果，不合并文本中不同位置的写变量操作。随机、变量和世界书状态沿用平台 Session 与 retry snapshot。

平台 `{{file:...}}` 返回的正文不会递归解释 Content，因此外部 MD 中的宏由生成的渲染脚本处理。编译文本修改后必须重新转换，不能使用旧索引解释新文本。输入文本作为数据序列化，不作为可执行 JS 源码拼接；转换器不会执行源卡插件程序。

## 世界书转换与渲染接入

世界书匹配逻辑继续由通用 lib 负责，不为每个 entry 生成独立平台规则。原配置和 extensions 保留，自有字段只放在 `extensions.world_card_station`。ID 与文件名分离：优先使用原 ID，缺失时生成并记录稳定映射；重复 ID 报错。文件名优先取 name/comment，处理非法字符、大小写及 Unicode 重名并增加稳定后缀，无名称时使用可读的条目序号。

一条正文一个 MD，通过 `content_file` 关联；`files` 只注册 worldbook 目录及 include 范围，不逐条注册 entry。生成完整装饰器索引（无装饰器为 `[]`），并使其与 MD 同步。无正文的 entry 也保留其配置含义，不凭空补出内容。

lib 提供可选文本渲染回调，由卡专属 wrapper 通过普通 JS 函数调用传入；不是将函数塞进 exec 的 JSON args，也不是新增脚本权限。未传回调时保持库现有行为；编译接入路径不得再执行一遍原酒馆宏替换。

- 关键词在匹配前求值；正文在预算和递归扫描前求值，不能在最终消息插入后统一替换。
- 同条目本次调用复用求值结果；分别提供模型正文和扫描正文，隐藏键只参与递归，注释不进入模型或匹配。
- 世界书模式、渲染回调和角色锚点由转换器一并配置；不把库现有近似 token 预算标成模型精确 tokenizer。
- Outlet 在本轮结算后读取，清除上轮残留；只补待求值节点。条目依赖本轮自身 outlet 的循环先报告不支持，不用旧状态填补。
- 世界书支持静态、只读和随机宏；写变量宏不执行并报告不支持。

动态正文的生成规则/脚本应以卡内文本为依据；若使用编译期片段索引，需记录内容指纹并在修改后要求重新编译该文本，不能用旧偏移渲染新正文。原始酒馆 JSON 不作为自动覆盖用户修改的第二份运行时来源。

## 资源、安全与安装身份

CHARX 的 `embeded://` 和 PNG 的 `ccdefault:` 按 [V3 资源语义](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md#assets) 解析到受控本地资源；`ccdefault:` 不能无条件映射成任意类型的封面。受支持的 data URL 限量解码。旧式 PNG 扩展资源不读取，缺失时报告警告。

背景、表情等有明确对应关系时生成现有 visual 资源表；头像/封面没有对应展示槽位时保留，不冒充背景或自动显示立绘。音频仅归档，不自动注册或播放 BGM。视频、模型、插件代码等不自动加载执行；安全范围内只归档，无法保存的内容明确报告。

外部 URL 默认不自动下载，不读取 `file://` 或任意本地路径。仅有世界书名称而没有随卡携带数据时报告外部依赖缺失。所有资源通过已授权输入清单复制，不能访问用户酒馆安装目录寻找缺失文件。

沿用容器的路径、链接、重复文件、压缩和数量限制，并限制角色 JSON、Base64 解码、解析深度和编译输出规模。输入与输出都检查总量：现有 4096 文件上限包含千条 MD、生成脚本、库与归档；不能通过转换绕过。平台 schema、`$import`、资源引用和目录 scope 校验仍是最终边界。

首次转换生成新的安全 `card.id`，不以角色名、作者或未经验证的扩展 ID 作为覆盖依据。来源指纹用于归档追溯，不自动提示重复或作为安装身份；用户可新建副本或明确选择更新目标。更新前提示旧存档适配风险，沿用 Session 保留机制，不自动迁移剧情状态。

安装失败或取消不能留下半张卡、改变旧卡或误激活。替换目录和更新 active card 作为完整提交处理；激活失败也要恢复此前状态。转换版本、所用库版本、源指纹、转换选项和映射保存在 `import/`，不保存用户绝对路径或凭据。

## 兼容报告

报告分为 error（阻止安装）、warning（行为缺失/有损转换，提示继续或取消）、info（元数据、默认值和归档说明，不弹窗）。收藏等已知元数据、空扩展和空 depth prompt 仅记录说明；非空未支持扩展单独标明位置并警告，不能因原文已归档就视为兼容。每项包含稳定 code、源字段/entry/宏位置、原因、处理方式及影响；完整报告随卡保存在 `import/report.json`。

STscript、EJS/MVU、插件 UI、自动化、跨会话全局变量、完整酒馆预设及群聊不受支持；不能只删掉未知宏后显示“完整导入成功”。正则逐项转换或报告不支持，不把源插件脚本直接注册为游戏卡 UI 或 exec。
