# Web 端分步开发与验收计划

状态：已具备步骤 1 构建与测试骨架，以及步骤 2 静态发布工具和目录浏览；完整验收仍须通过浏览器矩阵和桌面回归，步骤 3–8 待实施。依据：[Web 版本设计](./web_version_design.md)。命令见[构建文档](./build_and_test.md)，发布规范见[静态发布说明](./web_static_release.md)，不表示已支持游玩。

## 1. 交付边界与执行规则

- 交付主站可信托管卡、全量资源缓存、模型直连、手动存档、存档转移与完整游玩闭环。
- 不做本地卡导入、开发者模式、账号、模型代理、商店或网页离线启动。
- 共用规则引擎、消息管线、脚本与演出；桌面端原有导入、自动保存和开发能力不得回退。
- 按下列步骤推进；每一步包含实现、自动化测试和可复现验收，退出条件通过后再进入下一步。
- 每步提交记录变更范围、实际测试命令、结果和未解决问题；失败或跳过不能记录为通过。
- 每个仓库文件不超过 200 行；新增功能同步补测试，不删除、弱化现有测试或覆盖率门槛。

## 2. 测试分层与基础设施

| 层级 | 验证对象 | 执行方式 |
| --- | --- | --- |
| 单元测试 | 路径、版本、下载状态机、保存策略、错误和 UI 分支 | 沿用 Jest；仅在依赖边界 mock |
| 集成测试 | Rust 发布产物、真实浏览器存储、资源 adapter、Worker、会话事务和网络解析 | 发布器真实执行；浏览器测试页调用实际模块，不替换 Cache Storage/IndexedDB |
| E2E | 玩家从目录到下载、游玩、保存、恢复、卸载和删除的完整行为 | 对生产 Web 构建运行浏览器自动化，通过 UI 操作和可观察结果断言 |
| 交付冒烟 | 真实模型、实际托管 CSP、真实浏览器及大型资源 | 独立验收，不替代前三层自动化 |

优先复用现有 WebdriverIO 和流式测试服务，新增独立浏览器配置，不依赖 Tauri WebDriver 插件。步骤 1 先验证浏览器驱动矩阵；测试基础设施不得进入生产构建。

维护最小测试卡，包含 `$import`、外部 schema、文件读取、exec、自定义 UI、背景、立绘、音乐、状态 patch、阅读游标和重试。增加第二来源及同卡第二版本，验证隔离；测试不读取 WA2 项目目录。

测试服务提供固定索引、真实发布文件、请求计数和可控 SSE；支持延迟、404、错误内容及中途断流。跨域测试使用不同 origin 的 HTTP 服务，真实处理 OPTIONS 和允许/拒绝 CORS，不用请求拦截假装浏览器跨域成功。

每个测试使用独立浏览器数据环境；刷新/重开、多标签页测试共享同一指定环境，不错误清空待验证存档。失败保留浏览器日志、截图、请求记录和测试报告，禁止收集真实密钥。

## 3. 步骤 1：双端构建与测试骨架

实现：
- 增加 Web 构建入口、输出目录及部署 base；桌面命令和产物保持不变。
- 定义 capabilities、手动/自动保存策略及明确的未实现能力错误；Web 不加载 native bridge。
- 建立浏览器集成测试页、生产产物静态测试服务、浏览器 E2E 最小启动用例，并从本步接入 CI。

测试与退出条件：
- 单元：入口选择、能力控制、不可用操作错误；Web 不订阅原生关闭或启动 trace。
- 集成：双端连续构建不互删产物；检查 Web 模块依赖图不含原生桥和 WebDriver 插件。
- E2E：生产网页在根路径和子路径均可启动，原生/开发/本地导入入口不可见，无启动异常。
- 桌面现有启动与平台接口测试通过；浏览器核心引擎矩阵均有可执行启动测试。中间版本尚不作为可游玩产品交付。

## 4. 步骤 2：静态发布协议与发布工具

实现：
- 确定索引、release 清单、不可变版本身份及跨端内容指纹规范。
- 复用 Rust 导入校验和 `$import` 展开，输出运行配置、完整资源、文件长度及哈希。
- 过滤 Session、trace、设置、绝对路径及开发私有内容；失败不发布半成品，不覆盖旧 release。

测试与退出条件：
- 单元/Rust：清单结构、路径安全、缺失资源、隐私排除、内容指纹；配置或资源变化改变内容身份。
- 集成：从最小源卡真实发布并重新读取验证；与桌面加载后的配置及内容指纹一致，不依赖容器包装字节。
- E2E：浏览器目录展示该产物名称、封面和版本，浏览列表只请求索引与封面。
- 产物可由普通静态服务器提供；失败发布不改变此前可用目录和版本。

## 5. 步骤 3：全量缓存与本地资源接口

实现：
- 按来源/卡片/release 隔离 Cache Storage；从清单检查齐全，缺失则有限并发下载。
- 加入大小和哈希校验、进度、取消、重试及空间错误；文件写入全部成功后提交就绪标记。
- 文本从缓存读取，媒体生成 Blob URL；保留资源授权、规则预加载和同步 readFile 语义。
- 建立最小 IndexedDB 发布引用/就绪记录；缓存操作与标记无跨库原子性，启动必须复查文件。

测试与退出条件：
- 单元：路径/来源限制、清单重复项、哈希不符、错误不永久缓存、并发限制和下载状态转换。
- 集成：真实 Cache Storage 写读、部分缓存补齐、就绪标记写入失败恢复、Blob URL 创建与释放。
- E2E：首次全部下载后可初始化；再次进入该版本不请求发布资源；删除一个缓存文件仅补该文件。
- 中断、404、错误内容或配额错误均不得进入半成品游戏，不改变旧版本和 Session；阻断发布服务器后完整缓存仍可初始化已打开网页中的游戏。

## 6. 步骤 4：模型、规则和演出运行闭环

实现：
- Web fetch 复用现有请求构造和 SSE parser，支持 OpenAI/Anthropic 协议、取消和错误。
- 接入真实 Worker、自定义 UI、背景/立绘/BGM、本地背景 Blob 和浏览器全屏。
- 加入资源就绪检查、失败重试及过期加载结果丢弃；密钥默认内存，主动记住才持久化。

测试与退出条件：
- 单元：SSE 分块、超时、HTTP 错误、取消、密钥记住/清除和过期资源结果处理。
- 集成：实际跨 origin 服务验证预检允许/拒绝，Worker 执行与超时、UI emit 修改状态、缓存媒体读取。
- E2E：下载卡片后通过模拟模型完成多轮，观察预期变量、文本、背景和立绘，音频就绪且用户操作后播放；失败可重试。
- 刷新后未记住的密钥不存在，取消记住后持久化密钥消失；不依靠绕过浏览器安全或自动播放限制完成测试。
- 同卡同初始状态及同模拟响应，在 Web 与桌面管线得到相同消息和游戏状态。此时尚不宣称会话持久化完成。

## 7. 步骤 5：完整 Session 与显式保存

实现：
- 事务保存完整快照和 revision，作用域及保存目标显式绑定，普通聊天独立隔离。
- 增加保存按钮、未保存标识、保存反馈及保存/放弃/取消离开流程；生成或状态操作期间禁用保存和导出。
- 保留内存 retry base；恢复失败禁写，保存失败保留现场，客户端继续自动保存。
- 实现跨标签页 revision 冲突保护和删除后拒绝迟到保存，不以广播代替事务检查。

测试与退出条件：
- 单元：dirty 状态、保存后新增修改、重试基准、切换三分支及失败不离开。
- 集成：真实 IndexedDB 事务中途失败无部分提交；来源/卡片/版本隔离、revision 比较及删除竞争。
- E2E：游玩不自动写进度，保存后刷新恢复完整快照；未保存后刷新回到旧快照；阅读位置和 retry base 保持正确。
- E2E：两标签页并发保存拒绝旧 revision；一个标签页切卡不改变另一个保存目标；读取/写入失败不覆盖旧档。
- 取消生成稳定后可保存未完成消息；普通聊天同样遵守手动保存，桌面自动保存回归通过。

## 8. 步骤 6：卸载资源与删除 Session

实现：
- 区分退出游戏、卸载资源和删除 Session；卸载支持明确版本范围或整卡所有版本。
- 卸载清理 Cache Storage 和就绪标记，保留引用与 Session；删除 Session 只改 IndexedDB 会话及索引。
- 卸载当前游戏先处理未保存进度并释放运行时；协调多标签页下载/卸载，防止迟到任务恢复已卸载资源。

测试与退出条件：
- 单元：操作目标、确认/取消、就绪标记清理和活动 Session 更新。
- 集成：删除缓存不触及会话；删除会话不触及缓存；卸载与下载交错完成、清理部分失败可重试。
- E2E：卸载后存档仍可见，打开后重新下载同版本并恢复；删除一个 Session 后其他会话和资源保持不变。
- E2E：删除最后一个会话返回列表；其他标签页不继续使用失效资源，旧保存不能复活已删会话；退出游戏不清缓存。

## 9. 步骤 7：跨端存档转移

实现：
- 定义统一 formatVersion、内容身份及完整快照；两端提供导出/导入，导入创建新 Session。
- 校验大小、结构和兼容性；Web 只接受可信目录匹配，不跟随存档内任意 URL。
- 导出当前稳定快照，不自动覆盖浏览器存档或清除 dirty 标识，不包含密钥/模型设置/本地路径。

测试与退出条件：
- 单元：未知格式、损坏 JSON、大小上限、内容不匹配、恶意来源、隐私字段排除。
- 集成：Web→桌面→Web 往返保留消息、变量、阅读位置及重试基准；容器差异不改变内容匹配结果。
- E2E：两端实际 UI 导出/导入，共享生成的测试存档验证继续游玩和重试；失败不改现有数据。
- 缺少可核验内容身份或目标版本不可用时明确拒绝；不按相同版本字符串静默兼容。

## 10. 步骤 8：部署、完整回归与发布验收

实现：
- 为实际静态托管配置 base、MIME、CSP 与缓存策略，先上传不可变 release，校验成功再更新索引。
- 将 Web 单元、集成、E2E 和生产构建全部加入发布门禁；更新架构、平台接口、构建命令和玩家说明。
- 保留上一版网页产物及旧卡 release，形成可执行回滚步骤；本步骤不自动授权正式上线。

测试与退出条件：
- Chromium、Firefox、WebKit 引擎矩阵执行核心浏览器集成与 E2E；WebKit 自动化结果不能冒充 Safari 验收。
- 当前稳定版 Chromium、Firefox、真实 Safari 验证缓存、存档、音频、全屏及子路径部署，记录版本和限制。
- 使用数百 MB 的合成资源执行下载、重入、卸载和修复验收，记录字节数、耗时、峰值内存及请求数；不把所有资源一次性载入内存。
- 配额耗尽/回收采用可控故障注入验证错误路径，另记录真实浏览器空间与持久化权限行为，不声称可精确模拟所有回收策略。
- 经配置授权的真实模型端点完成浏览器连接与一轮生成；自动化默认不消耗真实模型额度，未执行真实验收须明确记录阻塞。
- 选择一张现有可信游戏卡完成真实人工游玩验收，不将该卡内容变成平台自动化测试依赖。

## 11. 最终测试命令与交付门禁

以下 Web 命令已提供步骤 1 骨架；表中描述最终交付覆盖范围，后续各步继续补齐，不表示当前已有完整游玩测试。当前范围见[构建文档](./build_and_test.md)。

| 命令 | 必须覆盖 |
| --- | --- |
| `npm run test:web:unit` | Web 单元测试与组件分支；纳入现有覆盖率约束 |
| `npm run test:web:integration` | 发布工具产物、真实浏览器 adapter/存储/Worker/跨域集成 |
| `npm run test:web:e2e` | 生产构建上的完整用户路径与浏览器矩阵 |
| `npm run test:web` | 构建测试产物并串行组织以上三层，任一失败返回非零 |
| `npm run web:build` | 无原生依赖的独立静态产物 |

最终交付必须在同一提交上通过：lint、既有 JS 单元/集成测试、Rust 测试、Web 三层测试、双端构建，以及现有桌面 E2E（含独立酒馆导入 suite）。CI 沿用桌面三系统矩阵，不以 Web 通过代替桌面回归。

保留现有覆盖率门槛：分支 70%、函数 80%、行 85%、语句 82%。新增 Web 生产代码纳入统计，不以调整排除项规避覆盖；关键丢档、版本串用、半成品缓存和删除竞争场景必须有显式断言，覆盖率不能替代这些用例。

交付证据包含：提交号、产物、全部测试报告、浏览器版本、跨端往返结果、真实模型/大资源/实际部署冒烟记录及已知限制。尚有失败、未执行的必需测试或未解决的数据丢失问题时，不标记完成。
