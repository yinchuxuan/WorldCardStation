# World Card Station Web 版本设计

状态：目标设计；已具备双端构建、静态发布器和目录浏览，其余游玩能力尚未实现。日期：2026-09-20。

## 1. 目标与范围

在保留 Tauri 客户端的前提下，为同一平台源码增加静态托管的 Web 游玩端。同一份游戏卡内容可在两端运行，不复制 DSL、规则引擎、聊天管线或演出系统。

Web 定位为轻量游玩端：从主站选择游戏、连接自己的模型、直接游玩并手动保存进度。客户端继续承担完整游玩与开发能力，两端共享游戏语义，不要求功能和交互完全一致。

首期交付：双端构建、主站可信托管卡目录、全量资源下载与本地缓存、模型直连、浏览器显式保存、存档导入导出和核心游玩流程。以一张现有卡验证完整闭环。

首期不包含：账号、云同步、付费额度、模型代理、作者自助发布、完整游戏卡商店、任意 URL 卡片加载、本地卡包/项目目录/酒馆卡导入、网页离线启动、开发者模式及本地 Agent/CLI 网页化。存档文件导入不属于游戏卡导入，仍在首期范围内。桌面端现有能力继续保留。

“纯静态”指平台和卡片无需自有业务服务器；模型仍由外部服务计算，需要联网且允许浏览器访问。下载到浏览器的公开卡片规则和剧情不具备保密性。

## 2. 现状与迁移原则

当前 `src/renderer/` 承载共享 React 前端与桌面页面；`src/web/` 与 `src/tauri/` 平级，放置 Web 入口、专属页面和平台适配；`src/shared/game-card/` 为平台无关核心。`src/renderer/platform/` 的稳定入口通过构建别名选择平台实现。Web 已有启动页和静态目录，桌面 Rust 承担磁盘存储、卡片安装与模型 HTTP。

沿用现有业务接口，在平台边界新增 Web 实现。memory adapter 仍仅用于测试，不充当持久化生产实现。现有架构文档描述当前实现，本文描述拟新增能力。

| 能力 | Web 游玩端 | Tauri 客户端 |
| --- | --- | --- |
| 游戏来源 | 主站可信托管卡，固定版本资源缓存完整后游玩 | 保留本地卡包、项目与酒馆导入 |
| 进度保存 | 用户显式保存到当前浏览器 | 保留自动保存和切换前保存 |
| 开发与调试 | 无开发者模式、本机指引和磁盘 trace | 保留现有开发能力 |
| 模型连接 | 浏览器直连，受跨域限制 | 原生网络请求 |
| 窗口 | 浏览器全屏，无原生窗口操作 | 保留桌面窗口能力 |
| 存档转移 | 提供统一格式导入导出 | 新增同格式导入导出 |

能力声明负责入口与服务是否可用；保存策略负责自动或手动保存；adapter 负责存储、资源和网络实现。共享 DSL、变量、消息管线、重试语义、脚本、自定义 UI 和演出系统，不复制聊天运行时。

```text
React UI / chat runtime / game-card core
                  ↓
          构建时选择 platform
          ↙                 ↘
Tauri adapter             Web adapter
Rust / app_data_dir       IndexedDB / Cache Storage / fetch
          ↓                 ↓
桌面安装包                静态网页产物
```

## 3. 构建与模块边界

Vite 增加显式 Web 构建目标，保留现有桌面开发和打包命令。建议新增 `web:dev`、`web:build`，Web 输出 `dist/web`，桌面继续输出 `dist/renderer`，避免互相清理产物。

通过构建别名选择 Web/Tauri 平台入口；每个入口提供 gameCardPlatform、rendererServices、modelFetch 和 capabilities。业务模块不判断桌面环境，也不直接引入 Tauri API。Web 依赖图不得包含 native bridge、桌面窗口或 WebDriver 插件。

保留普通聊天入口。首期通过应用内状态选择预发布卡，不引入必须由服务器回退处理的深层路由。资源 URL 依据部署 base URL 解析，支持站点子路径。

## 4. 平台接口适配

| 接口 | Web 实现 |
| --- | --- |
| resources.readText | 根据卡片版本和清单，从 Cache Storage 读取授权文本 |
| resources.getImageUrl/getAudioUrl | 从该版本 Cache Storage 读取媒体，按需生成并回收 Blob URL |
| repository.getActiveCard | 返回已校验、已展开 `$import` 的卡；失败显式抛错 |
| scriptExecutor.run | 复用 Worker 执行器及 context/result 校验 |
| config | IndexedDB 保存非密钥设置；密钥策略见第 8 节 |
| sessions | IndexedDB 保存完整快照；共享流程按 Web 手动保存策略调用 |
| cards | 主站目录、发布引用、缓存检查与补齐、激活、卸载游戏资源 |
| background | 文件选择后保存 Blob，显示时创建并回收 Object URL |
| window | 提供可用的网页全屏能力；关闭 native 窗口能力不开放 |
| development / trace | 不提供开发者模式、本机指引和磁盘 trace，不启动相关服务 |

capabilities 显式声明 cardImport、localDevelopment、diskTrace、nativeClose 和 fullscreen 等实际能力。Web 隐藏导入卡片、开发者模式及原生窗口操作，且不订阅原生关闭事件或启动磁盘日志服务；仍提供玩家可理解的运行错误提示。不可用操作的意外调用返回明确错误，不使用“成功但无效果”的占位实现。

Web 使用“添加游戏/开始游玩”入口，自动检查并补齐缓存，不冒充 `cards.importFile()`。新增最小业务操作表达缓存准备及卸载，保留桌面导入与酒馆转换契约；不复用桌面卸载连带删除 Session 的行为。游戏引用与 Session 保留发布身份，卸载资源后仍可重新下载对应版本恢复进度。

切换/退出游戏仅释放运行时与 Blob URL，不删除缓存或存档。`unload` 在 Web 界面称“卸载游戏资源”：删除指定来源、卡片、版本的 Cache Storage 和本地就绪标记；整卡卸载清理该来源下该卡所有缓存版本，不删除发布引用或 Session。先处理未保存进度并退出受影响运行时，再清理资源；同版本下载与卸载串行协调，其他标签页收到通知后停止使用失效资源，读取缺失时也必须明确报错。

删除 Session 是独立确认操作：在 IndexedDB 事务内删除该会话快照、索引记录并更新活动会话指向，不删除卡片缓存。删除当前会话时退出旧运行时并切换其他会话；没有其他会话则返回列表，不通过迟到保存重新创建已删除会话。

Web 设置隐藏本机路径和开发选项，保留模型、背景与游玩设置，提供存档备份和本地数据删除入口。明确提示数据只保存在当前浏览器、不自动跨设备同步，清理浏览器数据可能删除存档。

## 5. 在线游戏卡与发布准备

首期使用主站可信的固定发布目录和一个静态索引，提供简单目录供玩家选择，不建设发布后台或完整商店。游戏卡目录继续作为创作源，既有 `.gamecard`/PNG 保持桌面分发形式。

发布工具复用 Rust 导入解析、schema 和资源校验，输出展开配置及独立资源；协议、内容指纹、收集范围与隐私边界见[静态发布说明](./web_static_release.md)。Rust/Node 只用于发布阶段，Web 运行时不依赖它们；不发布 Session、trace 或模型设置，不写入源目录绝对路径。

```text
cards/<card-id>/<release-id>/
  release.json          发布元数据及文件清单
  card.json             已展开 $import 的运行配置
  rules/ state/ ui/     规则、schema、脚本和样式
  images/ audio/        独立媒体资源
```

`release.json` 是新增的分发协议，不是第二份游戏卡 DSL。至少包含发布协议版本、cardId、cardVersion、不可变 releaseId、平台兼容要求、入口，以及文件的相对路径、字节数、哈希和类型。

静态索引给出简介、封面和 release 地址。releaseId 以内容摘要或唯一构建标识生成，不能仅依赖作者重复使用的版本号。浏览器只接受配置的可信发布源。

发布时先上传完整 release 并校验，再更新索引；已发布 release 不原地覆盖。已有会话引用的旧 release 应保留；本地缓存齐全时可继续使用，缺失资源且发布源已不可用时提示无法补齐，不能自动换成最新版本。

## 6. 加载、缓存与失败行为

1. 浏览列表只获取索引和封面；选卡或恢复 Session 时确定固定发布版本，不自动升级。
2. 检查该版本已校验的 release 清单、就绪标记和全部缓存条目；齐全则直接从本地加载，不要求重新下载清单或资源。不能仅凭缓存名称或 card.json 判断完整。
3. 缓存不存在或不完整时，从可信发布源获取缺失清单/文件，下载全部配置、schema、脚本、样式、文本、图片和音频；显示总大小及进度，支持取消和重试。复用已校验且完整写入的文件，不要求单文件字节级续传。
4. 每个文件下载时校验长度与哈希，通过后写入版本专属 Cache Storage；全部文件写入成功后最后提交就绪标记，才允许初始化游戏。失败不标记完成，不影响旧版缓存或存档。日常启动检查条目齐全，不逐次读取全卡计算哈希。
5. 初始化前从本地完成现有规则预加载；同步 `readFile` 仍读取已准备文本。目录 scope 和动态内容继续遵守 `files` 授权，路径必须落在清单和固定发布目录内，拒绝绝对路径、路径穿越和未授权协议。

Cache Storage 按 sourceId/cardId/releaseId 隔离，保存清单和完整资源；不是依赖浏览器普通 HTTP 缓存。adapter 主动读取缓存，媒体使用 Blob URL，不直接给媒体元素远程 URL 并假设会命中 Cache Storage。首期不引入 Service Worker；索引采用重新验证策略。资源本地化不承诺网页断网重启或模型离线可用。

全量下载不等于全部解码进内存；图片和音频按需读取，首屏及已知下一演出可提前解码准备。切换前资源未就绪保留旧画面并提示加载；图片/音频失败支持重试，不破坏已提交游戏状态。运行中缓存缺失时提示修复下载，入口、schema、规则或脚本缺失停止该次操作，保留内存进度及旧存档；不缓存失败 Promise 为永久结果。

下载采用有限并发、逐文件处理，不将整张卡全部读入内存再写入。下载前估算可用空间并保留余量，写入仍须处理配额不足；不能为下载资源自动删除存档。哈希用于完整性检查，不证明发布者可信；新版本单独准备，不覆盖旧版本。Cache Storage 与 IndexedDB 无跨库事务，就绪标记不能代替实际条目检查。

## 7. 存储、版本与存档转移

浏览器数据库拟命名 `WorldCardStationWeb`。使用版本化 IndexedDB schema；逻辑上分 settings、cardReferences（含缓存就绪标记）、sessions、backgrounds，必要索引在实现时确定。卡片文件放 Cache Storage，Session 放 IndexedDB；分开管理不意味着配额或浏览器清理行为隔离。

每个卡片引用包含 sourceId、cardId、cardVersion、releaseId 和 releaseUrl。会话作用域由来源、卡片和 release 唯一确定，再加 sessionId；普通聊天使用独立作用域，避免与卡片或不同来源同名卡混淆。

### 手动保存与离开行为

Web 会话进度采用手动保存策略，普通聊天同样适用；模型设置、背景和卡片登记等管理数据不受此策略限制。游戏过程仅更新内存，不因流式输出、回合完成、阅读位置或受控状态变化自动覆盖已保存进度。新会话可以建立空记录，初始化后的游戏进度仍需显式保存。

“保存进度”将完整快照写入 IndexedDB；“导出存档”下载当前完整快照，不要求先覆盖浏览器存档，也不清除未保存标识。界面显示未保存进度、保存中、上次成功保存时间及失败提示。生成、初始化或状态操作未结束时禁用保存和导出；生成取消后等待管线稳定，可保存未完成消息，但不得标记为生成成功。

切卡、切会话、返回游戏列表或卸载当前游戏资源时，有未保存修改须提供“保存并离开 / 放弃修改 / 取消”。保存失败不离开；放弃修改只丢弃内存进度，不覆盖旧存档。删除当前会话需明确确认同时丢弃未保存进度，取消则保留现场。

刷新或重新打开只恢复最近一次显式保存的快照；没有已保存进度时重新初始化。页面离开提醒仅作补充，不保证出现，不在关闭回调中偷偷自动保存。玩家需提前知道刷新、关闭或崩溃可能丢失未保存进度。

内存中的 retry base 仍在发送前维护，重试恢复本轮发送前状态，而不是上一次手动存档。阅读位置属于保存快照；恢复时保持现有 init 语义，但恢复和初始化不得自行写回覆盖存档。

### 持久化与冲突保护

一次会话保存须在同一事务中提交 messages、gameState、viewState、retryBase、metadata 和 revision。保留串行保存机制，但 Web 不启用自动保存或无条件切换前保存。保存期间后续产生的修改仍标记为未保存，成功反馈只对应实际提交的快照。数据库事务外先完成网络和数据准备，不跨网络请求保持事务。

每个标签页独立持有当前卡片与会话选择；加载和排队保存绑定明确的会话作用域及 revision，不在写入时重新解析共享的“当前活动卡/会话”。一个标签页切卡不能改变另一个标签页的保存目标。

初始化恢复失败时禁止保存覆盖旧记录。保存错误必须可见，内存中的最新状态保留以便重试或导出；不得静默退回内存并显示“已保存”。

多标签页采用事务内 revision 比较拒绝旧版本覆盖；冲突页面暂停保存与生成，提示重新加载或导出本地副本。广播通知可改善体验，但不能取代数据库冲突检查。

申请持久化存储、检查空间作为增强；申请失败不声称存档永久可靠。浏览器回收或用户清理站点数据可能同时影响缓存与存档；资源可重新下载不代表存档可恢复。配额不足提示导出与管理存储，不能自动删除其他会话。

### 存档转移

定义带 formatVersion 的独立 Session JSON 导出格式，包含完整快照、卡片身份/版本和导出时间；排除 API Key、模型配置、磁盘路径和资源缓存。导出不包含卡片媒体。

导入先校验结构、大小、兼容要求和目标卡片版本，再创建新 session；失败不覆盖现有数据，切入新 session 前也需处理当前未保存进度。Web 只匹配主站可信目录中的对应版本，不根据存档中的任意 URL 加载卡片或代码；版本不可用时明确提示。首期不自动升级旧存档到新卡版本。

跨端导入需匹配已安装/已发布卡片的内容版本。两端使用共同校验逻辑定义的内容指纹：基于规范化展开配置和运行资源，排除 Session 等可变数据及容器包装差异。不能只比较作者版本号、Web releaseId 或卡包字节哈希；缺少可核验信息时不得静默视为兼容。

## 8. 模型网络与密钥

Web modelFetch 使用原生 fetch、ReadableStream 和 AbortSignal，复用现有请求构造与 OpenAI/Anthropic SSE parser。模型服务必须支持当前网站来源、请求头及对应协议的浏览器请求。

保留 HTTP 错误、超时、流式中断和取消处理。浏览器 TypeError 可能来自网络或 CORS，提示“网络或跨域访问失败”，不能无证据断言具体原因。不得使用 no-cors 伪装解决响应读取问题。

密钥默认仅保存在内存；用户明确选择“在此浏览器记住”后才写入本地配置，并提供删除入口。未记住时刷新或重新打开需重新填写，关闭记住选项须删除此前持久化的密钥。本地保存不等于加密保险箱。平台不把共享服务密钥写进构建产物，不向静态托管端上传用户密钥。客户端保留现有密钥策略，两端共用请求构造、协议解析和连接测试。

首期不实现代理，不保证所有桌面可用端点都可在网页使用。真实服务验证使用明确配置的测试端点和凭据，自动化默认使用模拟流式响应。

## 9. 游戏卡代码与浏览器能力

保留现有 Worker 超时和数据校验；动态 React UI 和 Worker 不自动构成对恶意卡片的完整安全隔离。首期只加载审核过的卡片，未知发布源和用户上传代码不开放。

静态站部署显式设置适配现有动态 UI、Blob Worker、样式和媒体的 CSP，不直接复制 Tauri 的 local 协议策略。模型连接策略需要覆盖允许的外部端点；在浏览器中验证实际限制。

启动按钮提供媒体用户交互时机，处理浏览器拒绝自动播放和全屏请求的情况。对象 URL 在背景切换/卸载后回收。移动端响应式和音频行为纳入验证，但首期不承诺完整移动端产品适配。

## 10. 实施顺序

| 阶段 | 工作 | 交付与退出条件 |
| --- | --- | --- |
| A：浏览器运行闭环 | 双端入口、capabilities、最小发布准备、全量下载与 Cache Storage 资源适配 | 同卡资源齐全后初始化，模拟模型完成规则和演出；再次进入复用缓存；桌面可运行 |
| B：完整游玩与恢复 | IndexedDB、真实模型直连、手动保存、未保存离开确认、重试/取消、冲突保护 | 真实端点完成回合；刷新恢复最近显式存档；读取或保存失败不覆盖旧进度；跨标签页不串档 |
| C：交付验证 | 存档转移、版本核验、卸载/删除隔离、缓存修复、静态部署和桌面回归 | 网页独立托管，缓存清理后可下载恢复，同卡两端验收及存档往返通过 |

新增代码集中在 platform Web adapter、浏览器存储和发布准备工具。共享核心仅为实际契约缺口改动；不借迁移重写规则引擎或既有桌面存储。

## 11. 验证与验收

- 构建：Web 无 Tauri 运行依赖，双端输出互不覆盖；根目录和子路径部署均可启动。
- 适配契约：资源授权、卡片激活、错误传播、配置、Session 行为具有针对性测试。
- 差异化：Web 不显示或启动本地卡导入、开发者模式、磁盘 trace 和原生窗口能力；客户端原有入口与自动保存保持不变。
- 资源：首次补齐全部资源才开始，完整缓存再次启动不请求发布资源，部分缓存只补缺失文件；覆盖取消/中断、校验失败、配额不足、404、缓存被清理及版本隔离，半成品不得标记就绪。
- 手动保存：生成和状态变化不自动写进度；显式保存完整快照，刷新仅恢复最近存档；生成/状态操作期间禁用保存与导出。
- 离开与删除：切卡、切会话、返回列表和卸载验证保存/放弃/取消；保存失败不离开。卸载只清对应缓存及就绪标记，Session 保留；删除 Session 不删资源，迟到保存不得复活会话；跨标签页卸载/下载不竞争覆盖。
- 存档安全：保存后新增修改仍为未保存；重试独立于手动存档；未完成消息、配额错误、读取失败、版本缺失、双标签冲突和保存目标绑定均有测试。
- 数据与密钥：未记住的密钥不持久化，取消记住后清除已存密钥；导出不含密钥，导入不信任任意发布 URL。
- 模型：模拟流测试流式解析、取消和错误；配置测试服务后验证实际浏览器跨域与生成。
- 演出：背景、立绘、音乐、自定义 UI、脚本超时在目标浏览器实际验证。
- 跨端：同卡同初始状态和同模拟响应产生一致的游戏状态；存档往返保留消息、状态和重试基准。
- 回归：现有相关 JS/Rust 测试及 Tauri 核心流程保持通过；不以移除检查换取网页通过。
- 浏览器矩阵：当前稳定版 Chromium、Firefox、Safari 验证核心流程；记录实际版本和已知限制。
